## C — CONSTRAINTS & REQUIREMENTS

**Severity and binary decision rules.** Confirmed CRITICAL/HIGH violations reject; MEDIUM/LOW findings are advisory. CRITICAL means credential/private-mail exposure, unauthorized or duplicate sends, destructive data loss or a comparably severe reachable failure. HIGH means a concrete material correctness/reliability failure or a confirmed mandatory project-boundary violation. MEDIUM/LOW means nonblocking hardening, maintainability or style concerns. Every blocker requires a concrete path/scenario or direct mandatory-rule breach; uncertainty is not proof. Missing verdict-essential evidence yields insufficient data, not approval. Never downgrade uncertainty about a safety prerequisite into an advisory and approve. Do not invent load targets, coverage percentages, latency SLOs or legal duties.

Apply every specialty criterion below, recording applicability and evidence:

1. **Local web and tooling boundary.** Reject unexpected LAN/public listeners, network exposure or multi-user access without an explicit approved security design, remote/tunneled Tidewave access, production Tidewave inclusion, or disabled relevant CSRF/origin protections. Tidewave is dev-only code/SQL execution with access to local process data, not a harmless dashboard. Development-only documented tooling CSP adjustments are not a production CSP exemption. Idle scenery/focus mode is not a lock screen. Evaluate owner-auth requirements against current standards and the actual affected trust boundary; do not invent an authentication strategy.

2. **Authorization and input ownership.** Reject reachable Ash policy/IDOR or mass-assignment bypasses. Trace actor construction, actual authorizer configuration, policy evaluation/bypass semantics, accepted attributes, protected action callers and downstream ownership checks; DSL keywords alone are not proof of authorization. Verify public safe image/status reads remain distinct from internal service-actor writes. For mail paths, follow account identity to credential lookup and sink; one local owner does not justify mixing accounts or trusting browser selection as authorization.

3. **Sensitive-data containment.** Reject sensitive data exposed through inappropriate assigns/sessions, logs, telemetry, exceptions, jobs, fixtures, served files or commits, or a new undisclosed private-data flow. Inspect actual filtering/redaction, including ordinary HTML forms, Calendar IDs, OAuth/device parameters and error paths. Safe diagnostics retain allowlisted categories, not raw provider text, private metadata, request objects or exceptions. Generic scene request snapshots, known provider IDs and sanitized attempt/cleanup state are intended persistence, not a credential/provider-payload leak. The documented stock Bandit in-process conn-metadata exception is narrowly accepted; it does not authorize payload logging or export. Recognize synthetic keys/public dev defaults without inspecting secrets. Session signing is not confidentiality; require encryption/opaque references for sensitive session contents, not a blanket encryption-salt rule. SQLCipher does not protect unlocked processes, same-user code, browser copies or retained legacy plaintext; logical deletion is not forensic erasure.

4. **Owner, OAuth and credential lifecycle.** Verify paired first-run browser setup, protected ordinary credential POSTs before instrumentation, session guards/revocation and locked startup against current guides; terminal tools are explicit maintenance alternatives, not required first-run OAuth configuration. Google connections are not owner identities. Check single-use state/S256 PKCE, verified immutable subject binding, receiving-workspace intent, safe redirects, separate opt-in Calendar grants and shared disconnect semantics. GitHub App device authorization and installation discovery require both signed-in-user and app repository access; no obsolete PAT fallback. Rotating refresh-token claims are one-shot; unknown/interrupted refresh or failed rotated-token storage requires sign-in. Credentials remain in the dedicated password-unlocked file keychain, never runtime environment fallbacks, argv, jobs, SQL or browser-rendered values. No runtime login-keychain fallback, ACL broadening, initialized-key replacement or provider probe on credential save. Current guides govern exact credential namespaces and migration exceptions. Missing secure prerequisites for newly activated private-data paths block approval, but do not invent an owner strategy. Sending remains deferred; if introduced it needs explicit user/account/sender intent and no blind unknown-outcome retry.

5. **Hostile content, URLs and provider boundary.** Reject raw hostile email HTML, scripts/unsafe schemes, silent tracking content, unsafe redirects/outbound targets and secret forwarding. CSP alone is not sanitization. Use escaped text or an approved isolated rendering policy; explicit attachment preview/download and Calendar/GitHub links follow current guides, never automatic remote imagery. Stage credentials stay at the server HTTP boundary with fixed HTTPS, no redirects or automatic paid-POST retries, bounded responses/deadlines and safe errors. Background scenery explicitly uses provider storage and known interaction IDs for resume, with deletion after committed local publication; this is not a zero-retention promise. Generic art direction/request snapshots are allowed, but no private email, names, calendars, projects or dashboard context, browser Google calls, search grounding or remote references. Known-ID retrieval/deletion may retry safely without authorizing generation. Unknown submissions require charge/overlap acknowledgement then fresh cost confirmation, never automatic replay. No credential or raw provider/error payload belongs in persistence, UI or logs. Tests use fake keys/transports, never live/billable calls.

6. **Image validation before decoding/storage.** Reject MIME/extension mismatch, fail-open types and unbounded image decoding. Preserve current documented preflight limits: **10 MiB encoded image bytes, 8192 pixels per side, 16 million pixels total, 16 MiB streamed provider JSON**. Bound dimensions before native loading. PNG requires bounded static structure/chunk ordering, CRCs, inflation and scanline validation; APNG/unsupported types fail closed. PNG's permitted unused final-IDAT compressed-stream padding is not itself a defect; trailing bytes after IEND remain rejected. JPEG requires strict full pixel evaluation, warning-level decoder failure and decoded dimension/band/size checks, not header sniffing or lazy loading alone. Baseline/progressive 8-bit and grayscale JPEG are supported; unsupported frames/precision fail closed. Native Vix/libvips decoding is not a sandbox. Retained original bytes/metadata are not authenticated C2PA/SynthID provenance or a complete PNG reconstructed-color/conformance proof.

7. **Local file/image serving and scanner exceptions.** Reject traversal/symlink escape, catalog bypass, tamper exposure and arbitrary/provider-hosted image paths. Trace storage-root trust, exact digest/UUID filenames, bounded reads, atomic writes, owner-only files/directories, catalog membership and content-hash verification through serving. Canonical `.png` / `image/png` and `.jpg` / `image/jpeg` must agree across bytes, catalog, requested extension, route/controller and UI allowlists. Preserve previous-image/bundled-default fallback, restrictive CSP, `nosniff` and private cache handling; locked surfaces use only public bundled imagery. Published scenes have no count cap; bounded fallback history is not deletion authority. Publication/cleanup use cross-BEAM exclusion and the committed catalog. Re-evaluate affected narrowly annotated Sobelow storage invariants without freezing a helper count; reject blanket exclusions or annotations masking reachable unsafe paths.

8. **Self-hosting and provenance.** Reject runtime remote UI scripts/fonts/images, missing required third-party pins/licenses/provenance/checksums or undisclosed private-data transfer. Check actual imports, asset call sites and browser URL construction plus safe local provenance/license records. Self-hosted Space Grotesk and vendored GSAP have explicit provenance/checksum contracts; GSAP's custom license is not MIT. Server-side opted-in Gemini generation followed by validated local serving is not a forbidden browser remote-image dependency. Build-time dependency fetching is not a runtime CDN. Dependency-audit evidence is point-in-time and scoped: Hex audits do not comprehensively cover vendored JavaScript or native dependencies. Recommend appropriate caller verification rather than claiming an audit ran.

Accept safe synthetic fixtures, documented narrow storage-scan false positives while invariants hold, deliberately public non-sensitive state and app-wide stage scenery. Do not introduce public-site cookie banners, jurisdictional/legal regimes, consent infrastructure or enterprise assumptions for this personal app. These exceptions never waive a confirmed reachable blocker. Refer deep schema mechanics, side-effect lifecycle and end-to-end account separation to focused review when useful, but never suppress a confirmed blocker because another reviewer owns it.
