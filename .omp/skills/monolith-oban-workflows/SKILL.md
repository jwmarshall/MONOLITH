## Execution and recovery

1. Inventory every affected Task/spawn/start_async/assign_async, startup task, timer and worker, including purpose, owner, sensitive inputs, durability, cancellation/retry policy and disposition. Classify as durable application job, bounded synchronous local call or exact justified runtime primitive. Background provider reads/diagnostics/cleanup/polling/recovery belong in Oban, not browser lifetime. Retain necessary vault/security/session OTP services and UI-only observation timers; bounded native/transport isolation stays within its admitted operation/lease. Pre-unlock native work cannot depend on protected Repo/queues. Document narrow named exceptions, never a blanket security exemption.
2. Design authorized Ash admission and operation-specific state before coding. Capture immutable identity, generations, relevant request/day/selection revision and expiry. Commit durable intent and enqueue atomically, outside provider HTTP. Return a safe operation reference. Do not build a generic scheduler/task bus or duplicate Oban's state machine.
3. Keep jobs ID-only: opaque operation/account identifiers and safe revisions, never search/page/thread/provider content, prompts, codes/verifiers, tokens, actors, sockets or PIDs. Sensitive durable input belongs in scoped protected encrypted resources with bounded retention; credentials remain in the dedicated keychain. Keep job errors, metadata, events/logs/telemetry content-free. Private results need opaque authorized access, expiry and retention, not PubSub payloads.
4. Define correlation to jobs, queue concurrency/pending-work bounds, uniqueness/coalescing/expiry and result ownership. Obsolete navigation/search reads must not accumulate indefinitely. View exit may supersede reads but cannot cancel accepted durable cleanup/destructive work. Workers revalidate authorization, generation, vault admission, supersession and expiry before execution and publication.
5. Classify each effect: safely retryable read; one-shot paid submission; authorization-code exchange; rotating-token submission; cleanup with known identity. Protect irreversible effects with durable claims before submission. At-least-once delivery, rescue, uniqueness and max_attempts alone never establish exactly-once execution. Unknown outcomes stay explicit and never authorize replay; missing ephemeral OAuth inputs after restart require reauthorization. Retrieval/cleanup retries never permit another generation or token/code exchange.
6. Specify duplicate delivery, view exit/disconnect, missed PubSub, restart, account switch/reconnect, Lock during execution and native keychain access failure before implementing. PubSub invalidates; observers reload durable state after missed events. Oban completion does not imply provider success. Preserve honest failed/unknown/expired/cancelled outcomes. Protected queues/provider work stop on Lock; Escape/idle does not stop them. No promise of app execution while asleep/off.
7. Prepare synthetic tests for failed atomic enqueue, duplicate/rescued delivery, claim-before-call crash, unknown provider result, absent secrets, stale generation/request publication, missed-event reload, rapid obsolete UI work, view termination and Lock. Invoke monolith-background-work-reviewer before completion plus integration-reliability for effect semantics, account-isolation for fences, ash-sqlite/security-privacy for storage, test-reliability for evidence and cross-file for integrated contracts as applicable. Reviewers are scoped source reviewers, not runtime certificates.
